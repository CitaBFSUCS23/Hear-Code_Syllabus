七、教学重点

  1. 音乐-程序结构映射：反复↔循环、乐句↔函数、卡农↔递归、转调↔映射、和弦↔数据结构等。
  2. music21 对象模型：Note、Rest、Chord、Stream、Part、Measure、Score 的层次关系与创建/组合/分析/输出。
  3. 计算思维：分解（乐句函数）、模式识别（反复/模进）、抽象（数据结构表示和弦）、算法设计（迭代/递归/马尔可夫）、并发思维（线程/进程）。
  4. 乐理结构化：音程、和弦构成、功能和声、调式、曲式、复调入门。

八、教学难点

  1. 双重抽象：同时理解音乐结构与编程概念并建立映射。对策：先听后写、可视化支架。
  2. 从模仿到创作：后半段独立创作可能遇瓶颈。对策：模板+分阶段任务。
  3. 递归与高阶函数（★）：调用栈和函数作为参数是编程思维的跃升。对策：声部进入图、楼梯比喻，高中段跳过。
  4. 并发同步（★）：竞态条件与死锁抽象。对策：单乐器双声部不同步、乐团互相等待的音乐场景类比。
  5. 马尔可夫链（★）：条件概率与状态转移矩阵。对策：从音程频率统计的直观案例切入，本科段可适度引入矩阵表达与公式推导。
  6. 双端调试：代码报错与音乐「不好听」需分别诊断。对策：代码审查 + 聆听互评。
  7. 基础差异：高中乐理参差、编程仅入门；本科编程基础亦可能因生源不同有差异。对策：分层任务 + 同伴互助。

十、音乐与编程类比关系总表

以下 16 组映射是课程的知识骨架。标注 ★ 的为进阶课，高中段视情况开展。

#音乐概念编程概念具体解释
1音高 / MIDI / 频率变量 / 对象 / 属性每个音符有音名、MIDI 编号和频率三重属性，对应一个 Note 对象的多个属性；音高到频率是等比数列映射
2节奏 / 时值 / 拍号列表 / Stream 层次结构音符按时间排列在小节中，小节组成声部，声部组成总谱——对应 Stream 的 Measure→Part→Score 树形结构
3乐谱 / 演奏者 / 反复记号纸带 / 读写头 / 状态转移函数乐谱是纸带，演奏者的眼睛是读写头，大脑中的反复计数和速度力度是状态寄存器，反复跳跃规则是转移函数，Fine 是停机——演奏即图灵机计算
4反复 / 跳房子 / D.C. / D.S. if/else / while / 控制流乐谱中的演奏路径（第一遍走 1.、第二遍走 2.、D.C. 回头）本质上是一种控制流，与程序的分支和跳转逻辑同构
5乐句 / 乐段 / 动机函数 / 模块化 / 封装乐句有名字、可独立演奏、可被多次调用，正如函数有函数名、可独立定义、可被反复调用；乐段是乐句的组合
6 ★单乐器双声部 / 同一大脑多线程 / 共享内存 / 锁左右手各弹各的音符但共享同一个大脑（内存），必须对齐节拍（同步）；拍子不同步就是竞态条件，踏板就是互斥锁
7 ★乐团 / 指挥 / 乐手多进程 / 消息传递 / 死锁每个乐手有独立的乐器和分谱（独立内存），通过指挥手势协调（Queue 消息传递）；乐手互相等待无人开始就是死锁，四个必要条件可逐一打破
8力度 / 速度 / 演奏法函数参数 / 参数化 / 插值同一段旋律用不同力度和速度演奏产生不同情绪，正如同一函数用不同参数产生不同输出；渐强↔线性插值
9和弦 / 功能和声字典 / 集合 / 数据结构和弦是「同时发声的音符集合」，用半音数集合定义和弦类型（大三=[0,4,7]）；功能和声进行是和弦状态的转移规则
10模进 / 动机发展迭代 / 嵌套循环 / transpose动机在不同音高上重复（模进）= 循环中对数据做统一变换（transpose）；上行/下行模进对应递增/递减迭代
11 ★卡农 / 赋格 / 对位法递归 / 调用栈 / 延迟执行主题在不同声部隔几小节依次进入、互相追逐，正如递归函数隔几层调用依次执行；声部堆叠顺序=调用栈 LIFO
12 ★变奏曲 / 主题变形高阶函数 / 多态 / map同一主题用不同手法变奏（加花、节奏加密、转调）= 同一数据用不同函数处理；变奏函数即高阶函数的策略参数
13转调 / 移调映射 / 函数变换 / 模12运算把所有音符移高 N 个半音 = 对数据集做统一的函数映射；音高空间是模 12 的循环群，转调是该空间的平移变换
14 ★风格模仿 / 语料分析马尔可夫链 / 字典建模 / 统计音乐风格体现在「什么音后面接什么音」的统计规律中——用字典记录音程转移频率，构建马尔可夫链生成风格化旋律
15 ★音色 / 配器 / MIDI类与对象 / 封装 / 实例化同一音符用钢琴或小提琴演奏听感不同——同一数据用不同类的实例表现不同；乐器类封装了音色数据和演奏行为
16曲式结构 / 作品完整性架构 / 设计模式 / 项目整合歌曲有「主歌-副歌-桥段」的结构范式，软件有可复用的架构模式；完整作品需要模块化组织、接口设计和整体调试

拓展映射（随课插入，不设独立课时）：渐强渐弱↔插值算法、切分音↔异步/事件驱动、装饰音↔装饰器模式、节拍器↔时钟/调度器、MIDI↔序列化与协议、泛音列↔傅里叶变换、十二音序列↔排列组合。

十一、16 节课详细设计

模块一 / 第 1-4 课

声音与计算的基础——从音高数据到图灵机模型

建立「音乐即数据、乐谱即程序、演奏即计算」的核心认知。通过音高的数字本质、节奏的层次结构、图灵机的计算模型和曲式的控制流，复习 Python 基础并掌握 music21 的对象模型，为整个课程奠定理论基石。

01

音高的数字本质

MIDI、频率与 Note 对象模型

from collections import Counter

         if isinstance(n, note.Note)]

transitions = {}
for i in range(len(notes)-1):
    interval = notes[i+1].pitch.midi - notes[i].pitch.midi

random.seed(42)

for _ in range(16):
    if current in transitions:
        interval = random.choice(transitions[current])
        current += interval
    melody.append(note.Note(midi=current, quarterLength=1))

  4. 互评与颁奖（10分钟）：学生用评分表互评，评选最佳旋律/配器/创意/代码/展示等奖项；教师总结课程，强调「音乐是可感知的代码，代码是形式化的音乐」。

S学生任务

  1. 完成原创音乐作品的最终版本，确保代码正确运行、乐谱正确渲染、音频正常播放。
  2. 撰写创作说明（300-500 字），阐述创作意图、音乐手法、编程技术和遇到的困难及解决过程。
  3. 在音乐会上展示作品，清晰表达创作思路。
  4. 认真聆听同伴作品，填写互评表，给出建设性反馈。
  5. 反思整个课程的学习收获，完成课程自我评价表。

D设计意图

音乐会作为压轴项目，让学生综合运用所学知识，完成从「技能练习」到「独立创作」的跃迁；作品展示满足自我表达需求，创作说明与答辩训练元认知能力，同伴互评培养审美判断力。

课堂产出：16 小节以上（高中学段）或一首完整的原创音乐作品（本科学段），含乐谱 + 音频 + 源代码 + 创作说明。
课后延伸：优秀作品可制作成班级音乐专辑，或参加学校艺术节、科技创新大赛展示；鼓励学生将作品上传至 GitHub 或音乐平台分享。

十三、评价方式

本课程采用过程性评价与终结性评价相结合、多维度 rubric 的评价体系，评价标准与高中音乐和信息技术两大课程标准的核心素养对接，强调创作过程、跨学科理解和反思能力。

13.1 评价维度与权重

维度权重对接核心素养评价标准
技术实现25%计算思维代码正确运行；使用了当节课核心编程概念；代码结构清晰、命名规范、有注释；能独立调试错误
音乐创意25%审美感知、艺术表现旋律流畅、节奏有设计感；运用力度/速度/配器等表情手段；使用了课程所学音乐手法（模进/转调/变奏等）；音乐有情绪表达
跨学科理解25%计算思维+审美感知能口头或书面解释「这段音乐对应哪段代码、这段代码实现了什么音乐效果」；能在新的音乐现象中识别对应的编程概念；理解音乐与数学/计算的深层联系
学习过程15%数字化学习与创新积极尝试与迭代；遇到 bug 主动调试并解决；帮助同伴；课堂参与度；课后拓展完成情况
作品展示10%艺术表现+文化理解毕业作品完整性；展示表达清晰；创作说明有深度；能回答同伴和教师的提问

13.2 评价构成

  • 每节课课堂产出（50%）：每节课有一个小作品，教师给予星级+评语反馈。
  • 跨学科反思日志（15%）：每节课后学生记录「今天学到的音乐知识、编程知识、它们之间的关系，以及我还存在的疑问」。
  • 期中作品（15%，第 9 课后）：一首包含前 9 课知识点的乐曲或乐曲片段。
  • 期末毕业作品（20%，第 16 课）：完整原创作品 + 创作说明 + 现场展示与答辩。

13.3 评价原则

鉴于学生音乐基础和编程能力的差异，评价坚持「以进步幅度为重要参照」的原则：

  • 对音乐基础较弱的学生，重点评价其编程概念的掌握、乐理知识的进步和尝试的勇气；
  • 对编程基础较弱的学生，重点评价其音乐创意、审美判断和跨学科映射的理解；
  • 对学有余力的学生，提供拓展挑战（如实现赋格、二阶马尔可夫链、自定义乐器类等），评价其探究深度；
  • 鼓励同伴互助，互助表现纳入学习过程评价。

十四、课程的跨学科设计亮点

14.1 音乐作为内容：从「感性接触」到「结构理解」

课程让学生在编程中学习音乐，培养学生计算思维和艺术素养。学生可在「用代码做音乐」的过程中理解音乐的组织形式。回应高中音乐课标的「从音响本体和音乐表现要素体验音乐美感，领悟作品表现意图」的要求。

14.2 编程作为工具：从「控制台输出」到「创造性表达」

传统编程课交互形式单调，学生难以获得情感共鸣。本课程打破次元边际，程序作为创作的乐器。学生可直观了解列表推导式、递归、高阶函数、数据结构、面向对象等编程概念。学生在真实的创作场景中习得计算思维，而非在抽象的习题中机械记忆语法。

14.3 数学作为桥梁：从「公式记忆」到「结构感知」

课程中的数学是音乐与编程的桥接：

  • 十二平均律是等比数列（公比 21/12），频率计算是指数运算；
  • 音符时值是分数体系，小节约束是分数加法；
  • 和弦类型是半音数集合（大三=[0,4,7]），和弦构建是组合数学；
  • 转调是模 12 平移变换，八度等价是同余类；
  • 渐强渐弱是线性插值；
  • 马尔可夫链是条件概率与统计推断。

学生用数学理解音乐、用代码实现数学，三个学科形成良性认知三角。

14.4 计算音乐学：从「消费者」到「研究者」

音乐风格建模是本课程区别于一般音乐编程课的标志性内容。学生能够成为音乐的研究者。用代码分析巴赫的作品，统计音程转移规律，构建模型并生成新音乐。这是 MIT 21M.383 等大学课程的核心方法在高中阶段的适切性转化，为学生打开了「计算音乐学」「音乐信息检索」「AI 创意应用」等前沿领域的窗口。

14.5 双重反馈机制：逻辑判断与审美判断并行

传统编程课只有一种反馈：代码能不能运行。本课程有两种反馈：

  • 逻辑反馈：代码是否正确运行（语法/逻辑错误）；
  • 审美反馈：音乐是否好听（和声/节奏/情感是否到位）。

学生需要同时发展「计算正确性」和「审美判断力」。理性和感性的双管齐下，培养学生的完整思维。

14.6 设计思维贯穿始终

课后练习是「创作」，而非「刷题」。学生需要经历「构思→编写→试听→调试→迭代→分享」设计循环，在循环中培养创造力。期末音乐会要求学生从意图出发，选择合适的技术手段，反复打磨作品，并向他人阐述自己的设计决策。

十五、教学实施建议

15.1 课前准备

  • 确保设备安装 Python 3.9+、music21、MuseScore Studio 4，完成 MuseScore 路径配置
  • 建立课程示例代码库，每节课的示例代码和练习模板提前分发；
  • 准备音频/视频资源：MIT OCW 精选片段、经典音乐作品（巴赫众赞歌、莫扎特变奏曲、帕赫贝尔卡农等）；
  • 教师应完整跑通所有 16 课的示例代码，准备常见报错和音乐问题的应对方案；

15.2 课堂组织

教师应遵循「课堂引入、先听音乐、再写代码」的原则，确保学生在理解音乐概念的基础上再进入编程实践。讲授环节应采用「边写边讲」的 live coding 方式，避免静态展示代码或幻灯片，应当让学生参与构建过程。

15.3 差异化教学

  • 设置「基础 + 挑战」分层任务：基础任务确保所有学生能完成核心目标，挑战任务供学有余力的学生深入；
  • 提供音阶模板、和弦进行模板、旋律片段模板，降低「不知道写什么」的创作门槛；
  • 对编程基础薄弱的学生，提供部分代码骨架（skeleton code），让其填空而非从零开始；
  • 对音乐基础薄弱的学生，重点评价其编程概念的掌握和跨学科映射的理解；
  • 建立同伴互助机制：鼓励学生之间互相调试代码、分享创作技巧。

15.4 常见问题与应对

问题应对策略
学生乐理基础差课程在编程实践中嵌入乐理复习，不单独补课；提供「乐理速查卡」
Python 基础遗忘前 4 课以「Python 回顾 + music21 新授」方式进行；提供 Python 语法速查表
代码报错导致挫败建立「调试三步法」：读错误信息→定位行号→检查最近修改；鼓励同伴互助；教师准备常见错误 FAQ
创作瓶颈「不知道写什么」提供音阶模板、和弦进行模板、节奏型库；允许从模仿经典作品开始；鼓励「先做出来再改好」
递归等高阶概念难理解充分使用可视化（声部进入图、调用栈图），用卡农的听觉体验建立直觉；不要求一次讲透，允许在后续课程中反复接触
环境配置问题优先使用云端 Jupyter 环境避免逐台配置；课前准备环境检测脚本；配备助教或技术支持人员
课时不足部分乐理讲解和代码练习可布置为课前预习；第 16 课的作品完善可延伸至课外；核心代码每课控制在 30 行以内

15.5 跨学科协作模式

本课程理想情况下由音乐教师与信息技术教师协同授课：音乐教师负责乐理导入、作品赏析和审美评价，信息技术教师负责编程讲授和技术指导。若只能由一位教师承担，建议音乐教师侧重音乐内容、借助代码模板降低编程门槛，或信息技术教师借助课程提供的乐理讲解材料和音频资源弥补音乐专业知识。学校可将本课程纳入学生综合素质评价。
